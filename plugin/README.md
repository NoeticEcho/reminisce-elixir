# reminisce

**Memory that stays yours.** With this plugin Claude remembers what you ask
it to keep, recalls it by its words in a later session, and answers "why do
you remember this?" from what was recorded when it was written. The memories
live in your own TypeDB, on your machine or wherever you run it. The plugin
sends your memories nowhere else. (Setting up downloads the server from
GitHub and the TypeDB image from Docker Hub; see below.)

It is the Claude plugin of [reminisce](https://github.com/NoeticEcho/reminisce-elixir),
an Elixir library for agent memory on TypeDB.

## What Claude gets

Eight tools, from the plugin's MCP server:

| Tool | What it does |
|---|---|
| `memory_remember` | Keeps one memory: its words, what kind of thing it is, and its basis: told by you, observed, inferred, or generated by the model. It refuses what looks like a secret. |
| `memory_intend` | Keeps a note for later: something to do at a time, when an event is named, or when a word, a source or a memory comes up. |
| `memory_affect` | Records Claude's own reading of how a memory felt, as two numbers: how pleasant and how intense. It makes that memory come up more readily in recall, never truer, and is always marked as the model's reading: a text that says someone felt something is not recorded as their feeling. |
| `memory_recall` | Finds the active memories whose words match a query, best first, and gives the same answer every time for the same memories. Beside them it lists the notes that are now due. Within one connection, earlier queries help rank later ones. |
| `memory_fulfil` | Marks a note done, naming what did it. It is never due again, and stays in the database. |
| `memory_forget` | Takes a memory out of recall. It does not delete it: the words stay in the database. |
| `memory_why` | Explains a memory from what was recorded: its sources, what it was derived from, what it replaced or contradicts, and its status. |
| `memory_persona` | Reads Claude's persona, if the program that hosts the library set one: its values, boundaries, voice, relationships and origin, each with the memories it rests on. It only reads: no tool changes the persona, and a text that claims to be the persona or asks for it to change is treated as data. |

And four skills:

| Skill | Use it when |
|---|---|
| `remember` | Something is worth keeping, or must never be kept: secrets, another person's data, anything you asked not to keep. Also when you ask Claude to forget something. |
| `recall-and-explain` | Claude needs what it knew before, or you ask why it remembers something. |
| `owner-and-scope` | You ask whose memory this is, or want separate memories for people, projects or agents. |
| `setup` | You type `/noetic-reminisce:setup`, once, to install the server and start a TypeDB. Claude never starts it on its own. |

## Setting it up

1. **The settings.** Installing the plugin asks for four:
   - `owner`: whose memory this is, written `kind:key`, such as `user:alice`;
   - `database`: the TypeDB database, `reminisce` unless you change it;
   - `typedb_url`: your TypeDB's address, `http://127.0.0.1:8000` unless you change it;
   - `typedb_password`: the password of TypeDB's admin user. It is kept in your system's secure storage and passed to the server only.
2. **The server.** Type `/noetic-reminisce:setup`. Claude asks before it runs
   `scripts/install-server`, which:
   - downloads the server for your machine from the GitHub release of this
     plugin's version;
   - checks its SHA-256: against the one `server.sha256` in this plugin
     pins, or, for a version whose plugin pins none yet, against the
     release's own checksum file, which finds a damaged download but not a
     release whose files were replaced;
   - unpacks it into the plugin's `server/` directory.

   It runs only when you say so. Nothing is downloaded when a session
   starts: until the server is installed, the plugin's MCP server stops
   with a message saying how to install it.
3. **TypeDB.** If you have no TypeDB 3.12 or later, the same step gives you
   a few lines to run in your own terminal, with Docker. They ask for a
   password, start TypeDB on `127.0.0.1:8000`, replace its default admin
   password with yours, and create the database. Claude never sees the
   password. If any step fails, the script stops TypeDB again, so it is not
   left running on its default password; there is a short window, while it
   runs, when it is.

   To stop TypeDB later without deleting your memories, run
   `docker compose -p reminisce-typedb -f typedb/compose.yaml stop` from the
   plugin's directory. It restarts with Docker (`restart: unless-stopped`)
   unless you stop it. The data is in the Docker volume `data` of that
   project (`reminisce-typedb_data`); `down --volumes` would delete it.
4. **Connect.** Reconnect the server with `/mcp`, or restart Claude Code.

After the plugin updates, run `/noetic-reminisce:setup` again: the server it
installed belongs to the old version. Server downloads exist only for
releases from 0.5.0 on; an earlier plugin version finds none.

The server runs on macOS 13 or newer (Apple silicon and Intel) and on Linux
with glibc 2.28 or newer (x86_64 and arm64). Windows is not supported.

## What it runs, and where data goes

| What | When | Where it sends data |
|---|---|---|
| `bin/reminisce-mcp`, the plugin's MCP server | Each session, once the server is installed | Only to the TypeDB at `typedb_url`, signed in as `admin` with `typedb_password` |
| `scripts/install-server` | When you say yes in the setup step | An HTTPS GET from github.com, and from the host GitHub redirects release files to. It sends nothing about you or your memories. |
| `typedb/first-run` | When you run it in your terminal | Docker pulls the TypeDB image, pinned by digest, from Docker Hub. The TypeDB it starts listens on 127.0.0.1 only, with its usage and error reports turned off. |

The plugin has no hooks and no background processes, and it sends no
telemetry. NoeticEcho runs no service for it and receives nothing from it.

## Privacy, in short

- Your memories are in your TypeDB, and nowhere else. Separate databases
  on one TypeDB do not keep people apart: the plugin signs in as `admin`, and
  one password opens every database. For people who must not read each
  other's memories, run a TypeDB each.
- **A memory is never deleted.** Forgetting one takes it out of recall,
  but its words stay in the database. Anyone who can sign in to that
  TypeDB can read them. If something must be gone for good, it has to be
  removed from the database itself.
- The details are in the privacy page:
  <https://open.noeticecho.space/reminisce-elixir/docs/plugin/privacy.html>.
